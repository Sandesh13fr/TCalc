# CI Reporter (Workspace Advisor in GitHub Actions)

This document explains how Workspace Model Advisor runs against its own
repository inside GitHub Actions. It is generated by the
`workspace-advisor-report.yml` workflow and is intentionally **local-first**:
no telemetry, no cloud calls, no third-party analytics. All processing happens
on the GitHub Actions runner.

## Overview

| Workflow | Trigger | Purpose |
|----------|---------|---------|
| `ci.yml` | push to `main`, PRs to `main` | Build, test, package, smoke test, telemetry guard |
| `release.yml` | tag `v*.*.*`, `workflow_dispatch` | Build, test, package VSIX, attach to a draft GitHub Release |
| `workspace-advisor-report.yml` | PRs, `workflow_dispatch` | Run the WMA CLI on the repo and upload reports |

## What the report workflow does

1. Checks out the repository.
2. Installs dependencies with pnpm (corepack, Node 22).
3. Builds all packages with `pnpm build`.
4. Runs the WMA CLI in three modes against the repo root:
   - `wma report . --include-repo-map --output dist-ci/workspace-model-report.md`
   - `wma repo-map . --budget 16000 --output dist-ci/repo-map.md`
   - `wma recommend . --format json --output dist-ci/model-recommendations.json`
5. Extracts a short summary (total tokens, goal, recommended model tiers).
6. Uploads the three files as workflow artifacts.

## Artifacts

| Artifact | Path | Description |
|----------|------|-------------|
| `workspace-model-report` | `dist-ci/workspace-model-report.md` | Full Markdown report with embedded repo map |
| `repo-map` | `dist-ci/repo-map.md` | Standalone repo map, capped at ~16k tokens |
| `model-recommendations` | `dist-ci/model-recommendations.json` | Structured JSON, one `RecommendationResult` |

Artifact retention is 30 days. The `model-recommendations.json` is also what
the PR comment (trusted PRs only) is derived from.

## Running locally

You can reproduce the same output locally:

```bash
pnpm build
pnpm ci:workspace-report
# Outputs in ./dist-ci/
```

Or invoke the CLI directly:

```bash
node apps/cli/dist/index.js report . --include-repo-map --output workspace-model-report.md
node apps/cli/dist/index.js repo-map . --budget 16000 --output repo-map.md
node apps/cli/dist/index.js recommend . --format json --output model-recommendations.json
```

## Security

- **No telemetry.** No network calls are made from app code. The
  `scripts/check-no-telemetry.mjs` guard is run in CI on every push and PR.
- **Fork PRs are restricted.** The workflow's default token permission is
  `contents: read`. Pull requests originating from forks cannot post comments,
  but they still produce and upload the three report artifacts.
- **Trusted PRs get a short comment.** Only when `head.repo.full_name ==
  repository` does the workflow post a brief comment with totals and tier
  recommendations. No source code is ever included in the comment.
- **No third-party actions with elevated permissions.** The workflow uses only
  first-party GitHub actions (`actions/checkout`, `actions/setup-node`,
  `actions/cache`, `actions/upload-artifact`, `actions/download-artifact`,
  `actions/github-script`, `softprops/action-gh-release`).

## Concurrency

The report workflow uses `concurrency` to cancel duplicate runs on the same PR
when new commits are pushed. This avoids wasting CI minutes on stale results.
The release workflow does not cancel in-flight runs because tag pushes are
immutable and we never want to drop a build that produced a release artifact.

## Failure modes

- If the build fails, the report steps are skipped (the workflow does not
  depend on the main `ci.yml` to keep concerns separated, but a `pnpm build`
  failure will block the report itself).
- If the report commands fail, the `if-no-files-found: error` setting on
  `actions/upload-artifact` will surface the missing artifact.
- If a token does not have write permission (e.g. fork PRs with the default
  read-only token), the comment step is silently skipped and the artifacts
  remain available for download.

## How to read the report

Open `workspace-model-report.md` from the artifacts list. It contains:

- A header with the workspace path, goal, and privacy mode.
- File-by-file token estimates (largest first).
- A recommended model with reasoning, score breakdown, and warnings.
- The repo map (when `--include-repo-map` is used), capped at the CLI's
  default symbol/file budget.

For programmatic use, `model-recommendations.json` is the canonical output and
matches the `RecommendationResult` type in
`packages/core/src/types/recommendation.ts`.
